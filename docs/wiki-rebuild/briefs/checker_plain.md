# Phase 5 plain-language checker
For every page in your group (`SP/out/<Page>.md`), flag: (1) every technical term or acronym used before it is defined on that page or linked to `Words-You'll-See#anchor` (check the anchor exists in `SP/out/Words-You'll-See.md`); (2) every acronym not spelled out on first use on that page; (3) every symptom description not written from the user's point of view (must name where they look and quote the exact text in a code block, and say what did not happen); (4) every forward reference that breaks the concept map in `SP/wiki_ia_plan.md` (a page on a reading path relying on a concept whose home page comes later on that path) unless a one-line definition is given in place; (5) every first screen (the text before the first `##` after "In short") that is a wall of text: more than ~12 lines of prose without a list, table, code block or diagram; (6) every sentence a non-programmer would have to read twice: over ~30 words, nested clauses, passive voice hiding the actor, or two ideas; (7) the banned words: simply, just, obviously, easy, stuff, handle, deal with; (8) pages missing the anatomy order or the footer line; (9) code in prose where a name should be in words. One row per finding: page | line | quote | rule number | fix. Write to `SP/checks/plain_<group>.md`; return path + 5-line summary with counts per rule.

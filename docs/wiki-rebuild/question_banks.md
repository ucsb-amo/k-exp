# Question banks (editor-in-chief, Phase 0)

Acceptance: a fresh agent reading only the wiki answers every question correctly; a separate agent grades against the code. Newcomer answers within 2 clicks of Home; expert answers within 1 step of their natural entry point (search / Error Message Index / code map / Words You'll See).

## Newcomer bank (20)
N1. I sat down at kong after a power cut. What do I start, in what order, and how do I know each piece is up? (Expect: Server Dashboard on kong; LiveOD Server window says "Mother is watching..."; monitor server LED / Start on the Device Control panel; data drive B: mapped; env vars.)
N2. What is the difference between a run and a shot, and what is a scan? (shot = one execution of the sequence for one set of xvar values; run = set of shots with one run ID; scan = changing a parameter between shots.)
N3. Where do I type `ar mot_tof.py`, and what is `ar`? **[STALE 2026-10-10: a run queue went live 2026-10-09 and `ar` now means `kq run`; see HANDOFF §9b and re-derive the expected answer from the code once pushed]** (kpy terminal, from `kexp/experiments/default_experiments`; `ar` = ARTIQ's artiq_run via the shortcut in `kexp/_bat/shortcuts`; `art` = timed run.)
N4. How do I take a standard MOT time-of-flight run, and where does its data end up? (`ar mot_tof.py`; `B:\_K\PotassiumData\YYYY-MM-DD\<runid>_...hdf5`; liveOD saves the images.)
N5. What does `self.p.t_tof = 0.05e-3` mean, and what units do parameters use? (`self.p` is ExptParams; SI seconds; 50 µs.)
N6. How do I scan a parameter over several values, and how many shots will the run take? (`self.xvar('t_tof', np.linspace(...))`; shots = product of xvar lengths × N_repeats; absorption = 3 images per shot; printed as "Scan: ... -> N shots (M images)".)
N7. How do I look at the run I just took? (liveOD window live; data browser; `from waxa import atomdata; ad = atomdata(0)` in a notebook.)
N8. How do I load a run from last week if I know its run ID? (`atomdata(83120)`; positive int = run ID; 0/negative = relative to latest.)
N9. The terminal says `[LiveOD] Could not connect to LiveOD server`. What do I do? (Start the LiveOD Server on kong; check firewall/beacon; or pass `suppress_live_od=True` for a no-imaging run.)
N10. How do I stop a run that is going wrong? (Abort/Reset in liveOD; what Ctrl+C does to the device state; then Run MOT Observe if the state is untrusted.)
N11. What is the Monitor and the Device Control GUI, and when do my clicks reach the hardware? (Between runs, while the monitor is READY; Enter/focus-out sends; ~100 ms poll.)
N12. The Device Control GUI shows a red "untrusted" banner. What does it mean and what should I click? (A run took the core and its end state never arrived; Run MOT Observe puts the machine in a known state; Trust state asserts.)
N13. Which camera will my experiment use, and how do I choose a different one? (`camera_select=cameras.xy_basler` default in Base.__init__; keys in `kexp/config/camera_id.py`.)
N14. What is `Base.__init__(self, ...)` in every experiment, and what do `save_data` and `setup_camera` do? 
N15. Which file holds the default parameter values, and should I edit it or my experiment file? (`kexp/config/expt_params.py`; override in the experiment with `self.p.x = ...`; adopt as default only deliberately.)
N16. What are `kexp`, `waxx` and `waxa`, and which one do I open to find the MOT sequence? (`kexp/base/cooling.py`.)
N17. What does the `!!` banner about camera settings mean when a run starts or when I load data? (camera_overrides: the camera clamped a value; `camera_params` in the file stays the request.)
N18. How do I turn the MOT light on by hand without writing an experiment? (Device Control GUI → Composite tab → MOT card → On; or DDS tab; needs monitor READY; or Run MOT Observe.)
N19. How do I set up a new laptop for analysis only? (PC Setup: code folder, clone list, env vars `code`, `kpy`, `data`; `uv sync`; for now the full clone list.)
N20. My run finished, but no new file appeared in today's data folder. Where do I look first? (Was `save_data=True` and liveOD connected? `setup_camera=False` without liveOD only warns; `suppress_live_od=True` forces save_data False; `_lite`; liveOD log / GET_LOG outcome; run id 0.)

## Expert bank (20)
E1. `RuntimeError: [LiveOD] Could not connect to LiveOD server: ...` is raised in one run but another run only prints `Running experiment without LiveOD (setup_camera=False).` What decides raise vs warn, and in the warn case with `save_data=True`, is anything saved? (kexp/base/clients.py raise iff setup_camera; waxx/base/expt.py finish_prepare_wax prints "[LiveOD] WARNING: No liveOD server connection — data will not be saved (setup_camera=False)"; run_id stays 0; the `RuntimeError("No liveOD server connection found...")` branch is reachable only when save_data and setup_camera are both true, which Clients already raised on.)
E2. I made `frequency_tweezer_list` (a list param) an xvar. The host printed a new value each shot, but the kernel used the same value every shot. Why? (waxx/base/scanner.py generate_assignment_kernels writes kernels only for int/float/ndarray; lists and bools get no writer; KERNEL_INVARIANTS_PLAN "pre-existing bugs".)
E3. `ValueError: xvar key 't_tof' is already registered as an adjust param.` But calling `adjust` after `xvar` on the same key only prints a warning. What is the precedence rule? (scanner.py xvar() raises; adjust() warns "already an xvar; skipping adjust registration".)
E4. After a shuffled scan, `ad.params.t_tof` is not monotonic. Is it scan order or sorted order, and how does the analysis put shots back in order? (cleanup_scanned stores values in the order taken, no unshuffling; sort_idx/sort_N saved; atomdata unshuffles — confirm where.)
E5. An `RTIOUnderflow` happens in shot 7 of 20. Which cleanup kernel runs, is the data file kept or deleted, what does the Device Control GUI show afterwards, and what changes with `Base(save_on_underflow=True)`? (scanner._scan: cleanup_scan_kernel then `_abort_shot`; without the flag ABORT_RUN → liveOD deletes/handles the file and the exception re-raises with its core traceback; state reported UNTRUSTED because RTIOUnderflow ∈ WRITE_FAILURES; with the flag the run ends normally and saves 7 shots.)
E6. The terminal prints `[warmup] none: first shot likely ~25% low (Base(warmup_shots=2) to fix).` What are warm-up shots, do they trigger the camera, and do they appear in the data or liveOD? (base.py pre_scan; Cooling.warmup_kernel; no camera trigger, no DataVault write, no SHOT_COMPLETE.)
E7. `Run ID: 0` prints at prepare, then `Run ID: 83120` later. Where does the run ID come from, when is it assigned, and why does `fix_run_id.bat` fail? (RunInfo defer_run_id; INIT_RUN reply from liveOD; `%data%\run_id.py` counter via server_talk; `fix_run_id.bat` targets `waxa/data/increment_run_id.py`, which does not exist.)
E8. `!! run 83102: camera settings differ from ad.camera_params (the request): em_gain 300 -> 30 (clamped)`. Which value did the kernel's imaging timing use, which did the camera apply, and where is each recorded in the file? (`camera_params/` group = request, also what the kernel used; root attr `camera_overrides` JSON = applied; only written when something differs.)
E9. The SLM server window prints `Received command: ...` and `Mask: spot` but never the `-> mask: spot, dimension=...` line; the run saved SLM settings anyway. Were they applied, and what do the saved values mean? (Demon: LUT load failed / Remote Desktop; the writer thread stopped; experiments don't wait for a reply (or: reply added 2026-09-26 — check `slm_protocol.py` "reply when a pattern is applied"); saved values are the request.)
E10. An experiment stopped with `liveOD is serving a newer run; this run is stopped and nothing more of it is recorded`. What happened, and what happened to each run's data file? (Run tokens; a later INIT_RUN superseded it; old END_RUN/ABORT ignored; new file untouched.)
E11. Why does `atomdata(0)` sometimes load an older run than the newest file in today's folder? (server_talk `_is_completed_run`: a file with `run_complete=False` and no `run_finalized` is skipped; in-flight or crashed runs; before 2026-09-24 the fast path was dead because h5py returns numpy.bool_.)
E12. `[server_talk] WARNING: run ID 83120 maps to 2 data files: [...]. Loading ... This indicates a run_id collision.` How can this happen and which file is loaded? (matches[0]; two liveOD servers or a hand-edited `run_id.py`; reservation via `get_latest_run_id_any`.)
E13. Two monitor servers on the subnet: one refuses to start, and the beacon id is `monitor:86`. What is the 86 and what decides it? (waxx/util/comms_server/hardware_id.py: last octet of `core_addr` in the device db at `%db%`; plain `monitor` if unset.)
E14. `[Monitor] run 83120 aborted (RTIOUnderflow in a shot): its last commanded device state went to the monitor server, marked UNTRUSTED`. Why untrusted for an underflow but trusted for the liveOD Abort button? (WRITE_FAILURES in scanner.py: DAC_CH.set caches before writing, ramps only after the last point; abort snapshot kernel.)
E15. `AndorParams.frame_transfer = 1 is refused: ...` — at what point in the run is this raised, was a run ID consumed, and why is frame transfer never accepted? (prepare_image_array → prepare_for_run inside init_xvars/finish_prepare before INIT_RUN; no run id; SDK2 manual p.55 exposure semantics.)
E16. `[adjust] WARNING: adjustable params detected with save_data=True. Values changed in the Adjust panel between shots will NOT be reflected in saved data.` What exactly does the saved file record for an adjusted parameter? (params saved at END_RUN are the host ExptParams at end: the last adjusted value, one number, not per-shot; xvars are the only per-shot record.)
E17. `detune_d2_c_mot = -2.2` and `frequency_detuned_imaging = 24.e6`: what unit is each, and what does `self.p.imaging_state = 1.` vs `2.` change in `reset_devices`? (Γ vs Hz; F1 uses `frequency_detuned_imaging_F1`, F2 uses `frequency_detuned_imaging`.)
E18. `init_kernel` says DDS channels that still hold their PLL/SYNC setup were skipped. When must I pass `force_dds_init=True`, how is the outcome recorded, and which experiments force it? (waxx/control/ad9910_fast_init.py; Devices.init_all_dds; mot_observe.py forces it; outcome kept with the run's data per test_ad9910_fast_init.)
E19. A gated TTL input wait returns immediately, then the next shot underflows on its trigger wait. Why, and what prevents it? (stale input events in the TTLInOut FIFO; `cleanup_scan_kernel_wax` calls `ttl.clear_input_events()` every shot.)
E20. The camera never becomes ready and the liveOD log says `Could not apply the run's settings to camera andor ...`. Which Andor settings are refused outright, which are clamped and recorded, and where do I fix them? (amplifier mode `hs_speed`+`preamp` pair refused if not offered; run-owned fields refused; EM gain/exposure clamped → camera_overrides; `kexp/config/camera_id.py`.)
